# Componenta HTTP Emitter

Отправщик PSR-7 ответов для HTTP-приложений Componenta. Он отправляет статус, заголовки и тело ответа в PHP output.

Используйте пакет во внешней HTTP-точке входа после того, как PSR-15 конвейер вернул `ResponseInterface`.

## Граница пакета

Пакет только отправляет уже построенный ответ. Он не строит ответы, не создает серверные запросы и не запускает промежуточные обработчики. Для построения ответов используйте `componenta/http-responder`, а для HTTP-конвейера приложения — `componenta/app-http`.

## Установка

```bash
composer require componenta/http-emitter
```

`Componenta\Http\EmitterConfigProvider` публикуется через метаданные Composer.

## Основной API

`EmitterInterface::emit(ResponseInterface $response): void` отправляет ответ. `Emitter` — стандартная реализация.

```php
use Componenta\Http\EmitterInterface;

/** @var EmitterInterface $emitter */
$emitter->emit($response);
```

`Emitter` принимает необязательный размер чанка:

```php
$emitter = new Componenta\Http\Emitter(chunkSize: 16_384);
```

`EmitStrategy` управляет отправкой тела:

| Вариант | Значение |
|---|---|
| `Full` | Отправить все тело ответа. |
| `Partial` | Отправить тело ответа с диапазоном байтов. |
| `NoBody` | Отправить заголовки без тела. |

`EmitterException` выбрасывается при ошибках отправщика.

## Поведение во время выполнения

Перед отправкой `Emitter` проверяет, что заголовки еще не отправлены, и очищает активные буферы вывода. Затем он выбирает стратегию по статусу и заголовкам ответа:

| Стратегия | Когда используется |
|---|---|
| `NoBody` | Информационные статусы, `204`, `205` или `304`. |
| `Partial` | Статус `206` с заголовком `Content-Range`. |
| `Full` | Все остальные ответы. |

Для полных ответов отправщик добавляет `Content-Length`, если поток допускает перемотку, его размер известен и отсутствуют оба заголовка: `Content-Length` и `Transfer-Encoding`. Для потока без перемотки отправляется оставшаяся часть тела; её длина не выводится из полного размера потока. Поддержка диапазонов не объявляется автоматически: её определяет производитель ответа. Тело отправляется чанками и прекращается раньше, если клиент отключился.

Для частичных ответов отправщик передаёт уже подготовленное тело и сохраняет `Content-Range`. У ответа `416` сохраняется поясняющее тело. У ответа `304` сохраняется `Content-Location`, а тело не отправляется.

## Конфигурация

Провайдер регистрирует `Emitter` и псевдоним `EmitterInterface` на него. Обычно приложение получает отправщик из контейнера.

## Тесты

Запуск: `composer test`. Проверки HTTP-заголовков используют `php-cgi` рядом с текущим исполняемым файлом PHP; для другого расположения задайте `PHP_CGI_BINARY`. Без CGI эти проверки пропускаются. В CI следует установить CGI, чтобы проверялись и заголовки, и тело ответа.

## Контракт транспорта

Emitter отправляет подготовленный ответ через нативный PHP SAPI. `Content-Length` должен быть одним десятичным целым числом; для тела проверяется соответствие числа отправленных байтов. Неперематываемые потоки отправляются с текущей позиции. `Transfer-Encoding` и `Trailer` в ответах с содержимым отклоняются: транспортное кодирование выполняет HTTP-сервер. `Accept-Ranges` не добавляется автоматически. Для `X-Accel-Redirect` и `X-Sendfile` длина не выводится из пустого тела. Для 1xx/204 убирается фрейминг, для 205 задаётся `Content-Length: 0`, для 304 сохраняется явно заданная корректная длина представления. При нативном `REQUEST_METHOD=HEAD` тело не читается. Ошибка чтения либо отсутствие прогресса приводит к `EmitterException`. Если вывод уже начат, нельзя отправлять второй ответ. Поддерживаются Config 3 и 4.

`composer check` запускает PHPUnit и PHPStan. `composer benchmark` проверяет фактическую отправку через CGI для малых и больших тел, неперематываемого потока, 206, 204 и HEAD. Измерение включает запуск PHP-процесса и передачу через IPC; это сквозной замер SAPI, а не изолированный микробенчмарк класса.

Итоговый PSR-7 ответ определяет служебные поля CGI и заголовки представления: ранее установленные значения этих полей удаляются перед отправкой, а остальные нативные заголовки, например cookies сессии, сохраняются. Поле `Status` зарезервировано; `Location` и `Content-Type` не могут повторяться. Успешный ответ на `CONNECT` требует транспорта, поддерживающего туннель, и отклоняется этим отправителем SAPI.
